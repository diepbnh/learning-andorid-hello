Component Variant — hoàn thiện AppButtonColors.kt

Trước khi vào bài mới — bạn đã làm được nhiều hơn bài 1 yêu cầu: đổi màu hex cứng thành colors.primary, dùng lại AppButton thay vì viết Button mới, tự thêm Row 2 nút Light/Dark Mode với Modifier.weight(1f), và sửa Theme.kt để nền toàn app cũng đi qua theme. Đó đúng là cách một component-based UI nên được xây — bài này sẽ giúp bạn làm điều đó có hệ thống hơn.

1. Vấn đề: mỗi lần gọi AppButton phải tự nhớ đúng màu

Hiện tại AppButton nhận trực tiếp một Color: 

AppButton(text = "Login", backgroundColor = colors.primary)
AppButton(text = "Save",  backgroundColor = colors.danger)

Không có gì ngăn ai đó gõ nhầm colors.secondary ở một nút Login khác, hoặc còn tệ hơn là hardcode lại Color(0xFF1a75cf) — đúng cái bạn vừa sửa ở bài 1. Bạn đã cảm nhận đúng vấn đề này: file AppButtonColors.kt đang có một enum class bị comment, bỏ dở. Bài này sẽ hoàn thiện nó.

2. Khái niệm mới: enum class và when

enum class là cách khai báo một danh sách cố định, đóng các lựa chọn hợp lệ — giống property "Variant" trong Figma (Primary/Secondary/Danger...), khác với việc truyền tự do bất kỳ giá trị màu nào.

Thiết kế (Figma variant) 
Button
  variant: Primary | Secondary | Danger
Kotlin 
enum class AppButtonColor {
    Primary,
    Secondary,
    Danger,
}

when là cách "rẽ nhánh theo từng case" — giống if / else if nhiều lần, nhưng rõ ràng hơn và Kotlin sẽ báo lỗi lúc build nếu bạn quên xử lý một case trong enum. Bạn đã vô tình thấy đúng pattern này rồi — mở lại AppTextField.kt mà bạn từng đọc, có sẵn hàm này: 

fun appTextFieldBorderColor(
    isError: Boolean,
    isFocused: Boolean,
    colors: AppColors,
): Color = when {
    isError -> colors.danger
    isFocused -> colors.primary
    else -> colors.light
}

Bài này bạn sẽ viết một hàm tương tự — nhưng rẽ theo enum thay vì theo Boolean.

3. Thực hành: hoàn thiện AppButtonColors.kt

  1. Mở ui/components/button/AppButtonColors.kt, xóa phần comment cũ.
  2. Viết enum với 4 case, đặt tên khớp các token màu đã có trong AppColors (xem lại Color.kt nếu quên tên): 
    enum class AppButtonColor {
    Primary,
    Secondary,
    Danger,
    Light,
}
  3. Ngay dưới enum, viết một hàm @Composable map từng case sang theme token, dùng đúng pattern when vừa học: 
    @Composable
fun AppButtonColor.toColor(): Color = when (this) {
    AppButtonColor.Primary   -> colors.primary
    AppButtonColor.Secondary -> colors.secondary
    AppButtonColor.Danger    -> colors.danger
    AppButtonColor.Light     -> colors.light
}
    Đây gọi là "extension function" — fun AppButtonColor.toColor() nghĩa là gắn thêm hàm toColor() vào enum, gọi được như AppButtonColor.Primary.toColor(). Chưa cần hiểu sâu, chỉ cần chép đúng cú pháp này.
  4. Sửa AppButton.kt: đổi tham số 
    backgroundColor: Color = colors.danger,
    thành 
    variant: AppButtonColor = AppButtonColor.Primary,
    và bên trong ButtonDefaults.buttonColors(...), đổi containerColor = backgroundColor thành containerColor = variant.toColor().
  5. Sửa lại từng chỗ gọi AppButton trong LoginPage.kt và ResetPasswordPage.kt: đổi backgroundColor = colors.primary → variant = AppButtonColor.Primary, và backgroundColor = colors.danger → variant = AppButtonColor.Danger.
  6. Chạy lại app. Đây là refactor, không phải thêm tính năng — UI phải trông giống hệt trước. Nếu màu nào đổi khác đi, đó là dấu hiệu bạn map nhầm case trong bước 3.

Nếu Android Studio báo lỗi "when" expression must be exhaustive — đó chính là Kotlin đang bảo bạn còn thiếu một case trong when. Đọc thông báo lỗi, thêm case còn thiếu. Nếu vẫn không hiểu lỗi, hỏi agent ngay, dán nguyên thông báo lỗi.

"Vậy tôi phải nhớ thêm một API mới?" — Không phải nhớ thêm, mà là đổi thứ phải nhớ: trước đây bạn phải tự nhớ đúng tên token (colors.primary, colors.danger...) mà không ai nhắc nếu gõ sai; giờ chỉ cần gõ AppButtonColor. trong Android Studio, IDE tự gợi ý đúng 4 lựa chọn hợp lệ, và gõ sai tên sẽ báo lỗi ngay khi gõ thay vì để sai màu lọt tới lúc chạy app. Đây là đánh đổi tiêu chuẩn của mọi design system: giới hạn lựa chọn để đổi lấy autocomplete + kiểm tra lúc build.

4. Kiểm tra nhanh

1. enum class trong Kotlin dùng để làm gì?
2. Lợi ích chính của when so với nhiều if/else if là gì?
