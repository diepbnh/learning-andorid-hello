Bài 1 / Mission: Jetpack Compose UI cho Designer

Đọc hiểu Composable đầu tiên — rồi tự tay sửa nó

Mục tiêu của bài này không phải "hiểu hết Compose" — mà là làm được đúng một việc: chạy app thật trên máy/emulator, tìm đúng dòng code, sửa một chỗ, và thấy nó thay đổi. Đó chính là vòng lặp "code & debug UI" mà bạn sẽ dùng mỗi ngày sau khóa học này.

1. Composable = một "component" web, không phải một trang

Trong project hello của bạn, đây là component nút bấm đã có sẵn ở app/src/main/java/com/example/hello/ui/components/button/AppButton.kt:

Tư duy web (giả định) 
function AppButton({ text, onClick, bg }) {
  return (
    <button
      style={{ background: bg }}
      onClick={onClick}
    >
      {text}
    </button>
  );
}
Compose thực tế (AppButton.kt) 
@Composable
fun AppButton(
    text: String,
    onClick: () -> Unit,
    backgroundColor: Color = colors.danger,
) {
    Button(
        onClick = onClick,
        colors = ButtonDefaults.buttonColors(
            containerColor = backgroundColor
        )
    ) {
        Text(text = text)
    }
}

Giống nhau ở điểm mấu chốt: một hàm nhận tham số (props), và "vẽ ra" UI bên trong nó. Khác biệt: hàm Compose có @Composable phía trên — đó là dấu hiệu báo cho Compose biết "hàm này vẽ UI, hãy theo dõi nó để tự vẽ lại khi dữ liệu đổi".

Text/Button/Column... cũng là composable — do Google viết sẵn. AppButton là composable do project của bạn viết, gọi lại các composable có sẵn đó bên trong.

2. Modifier = chuỗi CSS, không phải một thuộc tính

Trong AppButton.kt, dòng này:

modifier.height(60.dp).widthIn(min = 200.dp)

đọc giống hệt việc viết class="h-60 min-w-200" — mỗi lời gọi hàm nối thêm một mảnh style, và thứ tự nối có ảnh hưởng (giống thứ tự class trong CSS cascade). Xem thêm bảng đối chiếu đầy đủ ở reference cheat sheet.

3. Bây giờ: chạy app và tự tay sửa một chỗ

Mở project hello trong Android Studio, rồi làm theo các bước sau:

  1. Bấm nút Run ▶ (hoặc Shift+F10) để build và chạy app lên emulator/thiết bị thật. Bạn sẽ thấy Login Page hiện ra.
  2. Mở file LoginPage.kt (cùng thư mục com.example.hello).
  3. Tìm dòng text = "Login Page". Đổi thành một câu bất kỳ, ví dụ "Chào bạn".
  4. Tìm dòng color = Color(0xFF1a75cf) ngay bên dưới — đổi mã màu hex thành một màu khác, ví dụ 0xFFE91E63.
  5. Chạy lại (hoặc dùng Apply Changes ⚡ nếu app đang chạy) và quan sát: chữ và màu đổi ngay trên màn hình app.

Nếu app không build được: đọc kỹ dòng đỏ trong tab Build ở dưới Android Studio — nó luôn chỉ đúng số dòng và lý do lỗi (thường là thiếu dấu ngoặc hoặc dấu phẩy). Đây chính là kỹ năng "debug UI" — đọc lỗi, sửa, chạy lại.

Nếu bị kẹt ở bước nào — app không chạy, không tìm thấy dòng code, hoặc lỗi lạ hiện ra — hỏi ngay agent (Claude) đang dạy bạn khóa này. Dán nguyên thông báo lỗi vào, đừng tự đoán.
