Tự dựng một màn hình mới — Sign Up Page

Đã build thành công. Bạn tự sửa đúng lỗi AppButtonSize.medium → Medium sau khi được chỉ hướng đọc lỗi build — đúng vòng lặp code/debug từ bài 1. Ba bài qua bạn đã có đủ các khối để lắp UI: AppTextField, AppButton (có size), theme token (colors.xxx), layout (Column/Row/Spacer), và state (remember { mutableStateOf(...) }). Bài này không dạy khái niệm mới về Composable — thử thách là tự quyết định cách lắp chúng lại thành một màn hình hoàn toàn mới, không sửa file có sẵn.

1. Nhiệm vụ

Tạo một màn hình Sign Up mới, độc lập với LoginPage/ResetPasswordPage, gồm:

  • Tiêu đề "Sign Up" (dùng lại style = titleXLarge, color = colors.primary — giống các trang khác)
  • 3 AppTextField: Username, Password, Confirm Password
  • 1 AppButton "Sign Up" (chọn variant/size tùy bạn)
  • 1 dòng text "Back to Login", bấm vào thì quay lại trang Login (giống cách LoginPage điều hướng sang Reset Password)

File mới: app/src/main/java/com/example/hello/SignUpPage.kt, cùng package com.example.hello, cùng chữ ký hàm với các trang khác:

@Composable
fun SignUpPage(modifier: Modifier = Modifier, navController: NavController) {
    // ... phần còn lại tự viết, dựa theo cấu trúc LoginPage.kt
}

2. Khái niệm mới (nhỏ): thêm một route vào NavHost

Màn hình mới cần một "địa chỉ" để navController.navigate(...) đi tới được. Mở MainActivity.kt, bạn sẽ thấy NavHost hiện chỉ có 2 route: 

NavHost(navController = navController, startDestination = "login") {
    composable("login") { LoginPage(...) }
    composable("reset_password") { ResetPasswordPage(...) }
}

Thêm route thứ 3, cùng khuôn:

composable("sign_up") {
    SignUpPage(modifier = Modifier.fillMaxSize(), navController = navController)
}
Tư duy web 
<Route path="/sign-up"
  element={<SignUpPage />} />
Compose 
composable("sign_up") {
    SignUpPage(...)
}

Sau đó, ở LoginPage.kt, thêm 1 dòng Text điều hướng sang route mới — copy đúng cấu trúc của Text "Reset Password" đã có sẵn (Modifier.clickable { navController.navigate("...") }), chỉ đổi route thành "sign_up".

3. Việc bạn tự quyết định — không có đáp án duy nhất

Không có hướng dẫn từng dòng cho phần này, vì đúng ý nghĩa của bài. Vài câu hỏi để tự trả lời khi viết:

  • 3 AppTextField nên đặt tên biến state là gì? (gợi ý: cùng cách bạn đã thấy trong ResetPasswordPage.kt — có cả 2 cách viết state, val x = remember { mutableStateOf("") } và var x by remember { mutableStateOf("") }, dùng cách nào cũng được, miễn nhất quán)
  • Password và Confirm Password nên hiển thị dạng ẩn ký tự (giống ô nhập mật khẩu thật) không? Nếu muốn, đó là một câu hỏi hay để hỏi agent — chưa được dạy trong bài nào, đúng lúc mở rộng khi bạn cần.
  • Nút "Sign Up" nên dùng variant/size nào? Tự quyết theo mắt thẩm mỹ của bạn.

Nếu cần một thành phần chưa học (ẩn ký tự mật khẩu, validate email...) — hỏi ngay lúc cần, đừng tự đoán rồi chép đại một đoạn code không hiểu. Agent luôn ở đây để giải thích thêm.

4. Kiểm tra nhanh

2. SignUpPage.kt nên dùng OutlinedTextField gốc hay AppTextField?
