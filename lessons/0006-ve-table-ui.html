Vẽ Table: chỉ làm UI, dữ liệu viết sẵn

Phạm vi bài này: chỉ dựng giao diện của một bảng, với nội dung gõ thẳng vào code. Việc lấy dữ liệu từ danh sách để tự sinh ra các hàng sẽ học ở bài sau. Những gì bạn đã có sẵn: Row/Column, theme token, một component nhận modifier (bài 4), và if … else cho ra giá trị (bài 4).

Kết quả mong đợi

Bảng 3 cột × 4 hàng (1 hàng tiêu đề + 3 hàng dữ liệu). Nội dung chữ là dữ liệu mẫu, bạn có thể đổi tùy ý.

Chú ý khi so sánh với app của bạn: cột "Sản phẩm" rộng gấp đôi hai cột còn lại (weight 2f / 1f / 1f). Hai cột số căn phải. Hàng tiêu đề nền colors.primary chữ trắng. Hàng thứ 2 nền nhạt (zebra). Mỗi ô có viền, nên các đường kẻ dọc và ngang tạo thành lưới liền mạch. Các ô trong một hàng cao bằng nhau. Bảng có viền ngoài và bo góc 8dp. Hình vẽ bằng HTML/CSS nên có thể lệch vài pixel so với Android, nhưng bố cục phải giống.

1. Compose không có thẻ <table>

Trong Compose, bảng chỉ là một Column chứa nhiều Row. Mỗi Row là một hàng, mỗi Text trong hàng là một ô.

HTML 
<table>
  <tr><th>Sản phẩm</th><th>SL</th></tr>
  <tr><td>Áo thun</td><td>2</td></tr>
</table>
Compose 
Column {
  Row { Text("Sản phẩm"); Text("SL") }
  Row { Text("Áo thun");  Text("2")  }
}

Có một khác biệt quan trọng. <table> của trình duyệt tự canh các cột thẳng hàng với nhau. Các Row trong Compose thì không biết gì về nhau, nên bạn phải tự làm cho cột thẳng hàng.

2. Khái niệm mới: Modifier.weight(), giống đơn vị fr trong CSS Grid

CSS Grid 
grid-template-columns:
  2fr 1fr 1fr;
Compose 
Text(..., Modifier.weight(2f))
Text(..., Modifier.weight(1f))
Text(..., Modifier.weight(1f))

weight chia phần chiều ngang của Row theo tỉ lệ. Tổng là 2 + 1 + 1 = 4 phần, nên cột đầu được 2/4, tức một nửa. Bạn đã dùng weight(1f) để chia đều 2 nút Light/Dark ở bài 1 (Compose modifiers — Android Developers).

Bí quyết để cột thẳng hàng: mọi hàng đều dùng cùng một bộ weight (ví dụ 2f / 1f / 1f). Chỉ cần một hàng dùng khác là cột sẽ lệch. Đây là "grid" mà bạn tự giữ kỷ luật, giống việc dùng chung một layout grid cho mọi frame trong Figma.

3. Style bảng: viền, nền header, đường kẻ

CSSCompose
border: 1px solid; border-radius: 8pxModifier.clip(RoundedCornerShape(8.dp)).border(1.dp, colors.light, RoundedCornerShape(8.dp))
thead { background: ... }Row(Modifier.background(colors.primary))
td { padding: 12px }Text(..., Modifier.weight(1f).padding(12.dp))
td { border: 1px solid } (lưới cho mỗi ô)Text(..., Modifier.weight(1f).fillMaxHeight().border(0.5.dp, colors.light).padding(12.dp))
các ô trong hàng tự cao bằng nhau (align-items: stretch)Row(Modifier.height(IntrinsicSize.Min)) + fillMaxHeight() ở mỗi ô
text-align: right (cột số)Text(..., textAlign = TextAlign.End)
tr:nth-child(even) { background }Row(Modifier.background(colors.light.copy(alpha = 0.4f))) cho hàng chẵn, viết tay

clip cắt góc bo tròn để nền header không tràn ra ngoài góc, giống overflow: hidden. Thứ tự trong chuỗi Modifier có ảnh hưởng: clip phải đứng trước.

Viền cho mỗi ô. Mỗi ô vẽ viền 0.5dp của riêng nó. Hai ô cạnh nhau cộng lại thành một đường 1dp. Trong chuỗi .border(...).padding(12.dp), border đứng trước padding nên viền nằm ở mép ngoài ô, còn padding là khoảng đệm bên trong viền, giống box model CSS. Đảo thứ tự thì viền sẽ bó sát vào chữ.

Vì sao cần IntrinsicSize.Min? Trong CSS flex, các ô trong một hàng tự kéo dài cho cao bằng nhau (align-items: stretch). Trong Row của Compose thì không. Nếu một ô xuống 2 dòng, ô bên cạnh vẫn thấp và viền dọc sẽ bị đứt. Row(Modifier.height(IntrinsicSize.Min)) nghĩa là "hàng cao bằng ô cao nhất", còn fillMaxHeight() ở mỗi ô nghĩa là "kéo ô cho cao bằng hàng". Hai dòng này luôn đi cùng nhau (Intrinsic measurements — Android Developers). Dùng colors.light.copy(alpha = 0.4f) (màu light làm nhạt đi) thay vì colors.white để hàng chẵn vẫn đẹp khi bật Dark Mode.

4. Nhiệm vụ

Bước 1: tạo trang mới. Tạo TablePage.kt, thêm route "table" vào NavHost, rồi thêm một link từ TemplatePage đi tới trang này. Bạn đã làm việc này ở bài 3 (có thể dùng popBackStack() cho nút Back).

Bước 2: khung bảng và hàng header. Đây là phần mẫu, đã được build thử và chạy được:

Column(
    modifier = Modifier
        .fillMaxWidth()
        .clip(RoundedCornerShape(8.dp))
        .border(1.dp, colors.light, RoundedCornerShape(8.dp))
) {
    // Header
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .height(IntrinsicSize.Min)   // hàng cao bằng ô cao nhất
            .background(colors.primary)
    ) {
        Text("Sản phẩm", color = colors.white, fontWeight = FontWeight.Bold,
             modifier = Modifier.weight(2f).fillMaxHeight()
                 .border(0.5.dp, colors.light).padding(12.dp))
        Text("SL", color = colors.white, fontWeight = FontWeight.Bold, textAlign = TextAlign.End,
             modifier = Modifier.weight(1f).fillMaxHeight()
                 .border(0.5.dp, colors.light).padding(12.dp))
        Text("Giá", color = colors.white, fontWeight = FontWeight.Bold, textAlign = TextAlign.End,
             modifier = Modifier.weight(1f).fillMaxHeight()
                 .border(0.5.dp, colors.light).padding(12.dp))
    }
    // Bước 3: các hàng dữ liệu viết ở đây
}

Bước 3: tự viết 3 hàng dữ liệu. Nội dung do bạn chọn (ví dụ Áo thun / 2 / 150k). Mỗi Row đều cần .height(IntrinsicSize.Min), mỗi ô đều cần .fillMaxHeight().border(0.5.dp, colors.light).padding(12.dp). Dùng color = colors.text cho chữ, và cho hàng thứ 2 có nền nhạt (zebra). Không cần HorizontalDivider nữa, vì viền ô đã tạo đường kẻ ngang. Viết xong, bạn sẽ thấy chuỗi Modifier dài này lặp lại ở mọi ô.

Bước 4: tách component AppTableCell. Đặt ở ui/components/table/AppTableCell.kt. Vận dụng lại bài 4:

@Composable
fun AppTableCell(
    text: String,
    modifier: Modifier = Modifier,
    isHeader: Boolean = false,
    textAlign: TextAlign = TextAlign.Start,
) {
    Text(
        text = text,
        modifier = modifier
            .fillMaxHeight()
            .border(0.5.dp, colors.light)
            .padding(12.dp),
        // color: nếu isHeader thì colors.white, còn không thì colors.text
        // fontWeight: nếu isHeader thì Bold, còn không thì Normal
        textAlign = textAlign,
    )
}

Khi gọi, nơi gọi truyền weight vào: AppTableCell("SL", Modifier.weight(1f), isHeader = true, textAlign = TextAlign.End). Lý do: weight chỉ dùng được khi trực tiếp nằm trong một Row/Column, và độ rộng cột là quyết định của bảng, không phải của từng ô. Nguyên tắc này giống bài 4: khoảng cách bên ngoài do nơi gọi quyết định.

Lợi ích lớn nhất: chuỗi viền và padding giờ chỉ nằm ở một chỗ. Muốn đổi viền sang 1dp hay padding 8dp, bạn chỉ sửa trong AppTableCell.

Sau đó, thay mọi Text trong bảng bằng AppTableCell. Bảng phải trông y như cũ.

Bước 5: kiểm tra. Build, chạy thử, rồi chuyển qua lại Light/Dark Mode. Kiểm tra: các cột có thẳng hàng không? Viền dọc có liền mạch không? Thử đổi "Mũ lưỡi trai" thành một tên thật dài để nó xuống 2 dòng: các ô khác trong hàng đó phải cao theo. Hàng zebra có đẹp ở cả hai chế độ không?

Muốn thêm cột có badge màu (ví dụ "Còn hàng" nền xanh), hay bảng quá rộng cần cuộn ngang? Hãy hỏi agent, cả hai đều làm được mà không cần dữ liệu động. Báo "xong bài 6" khi xong.
