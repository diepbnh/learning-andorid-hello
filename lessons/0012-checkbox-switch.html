Bài 12 / Nhóm 2: Form · Lộ trình

Checkbox và Switch: type="checkbox" và ion-toggle

Bài 11: xong. AppCard dùng 2 công tắc hasShadow / hasBorder nên kết hợp được cả bóng lẫn viền. Đây là thiết kế riêng của bạn và có lý do rõ ràng. Bài này mở đầu Nhóm 2: Form. Bạn sẽ dùng lại State true/false đã rất quen, cộng thêm một ý tưởng mới quan trọng cho mọi ô nhập liệu: component không tự giữ State.

Kết quả mong đợi

Một trang Cài đặt. Switch "Chế độ tối" đổi theme thật của app. Nút "Lưu cài đặt" chỉ bấm được khi đã tích "Tôi đồng ý". Hình dưới đây bấm được, bạn thử bấm vào cả dòng chữ, không chỉ vào công tắc.

Chú ý khi so sánh: các nhóm nằm trong AppCard của bạn. Switch bật có rãnh màu colors.primary, nút tròn to hơn và chạy sang phải. Switch tắt có rãnh nhạt và nút tròn nhỏ. Checkbox tích có nền colors.primary. Dấu tích và nút tròn của Switch dùng colors.white, nên ở Dark Mode chúng có màu đen (đúng với theme của bạn). Bấm vào chữ cũng bật/tắt được, giống <label>. Nút "Lưu cài đặt" mờ đi và không bấm được khi chưa tích "Tôi đồng ý".

1. Checkbox và Switch cơ bản

Ionic 
<ion-checkbox
  [checked]="agreed"
  (ionChange)="agreed = $event.detail.checked">
</ion-checkbox>

<ion-toggle
  [checked]="notify"
  (ionChange)="notify = $event.detail.checked">
</ion-toggle>
Compose 
var agreed by remember { mutableStateOf(false) }
var notify by remember { mutableStateOf(true) }

Checkbox(
    checked = agreed,
    onCheckedChange = { agreed = it }
)

Switch(
    checked = notify,
    onCheckedChange = { notify = it }
)

Hai việc tách riêng, giống [checked] và (ionChange):

  • checked = agreed: hiển thị theo State (đang tích hay không).
  • onCheckedChange = { agreed = it }: khi người dùng bấm, Compose đưa vào giá trị mới (it, là true hoặc false), và bạn lưu nó vào State. it ở đây giống $event.detail.checked.

Nếu quên dòng agreed = it, bấm vào checkbox sẽ không có gì xảy ra. Checkbox không tự tích được, nó chỉ vẽ theo checked. Bạn đã gặp đúng chuyện này với onDismissRequest của Dialog ở Bài 10.

2. Ý tưởng mới: component không tự giữ State

So sánh với AppToggleButton bạn làm ở Bài 9:

AppToggleButton (Bài 9)AppSwitch (bài này)
State nằm ở đâubên trong component (remember trong component)bên ngoài, ở trang dùng nó
Trang có biết đang bật hay tắt khôngkhôngcó
Hợp vớihiệu ứng trang tríform: cần lấy giá trị để lưu hoặc gửi đi

Trong form, trang cần đọc được giá trị (ví dụ nút "Lưu" cần biết đã tích "Tôi đồng ý" chưa). Vì vậy component form nhận 2 tham số checked và onCheckedChange, còn State do trang giữ. Cách này gọi là state hoisting ("kéo State lên trên"), giống [(ngModel)] của Angular/Ionic: component chỉ hiển thị và báo thay đổi. AppTextField có sẵn của bạn cũng làm đúng như vậy với value và onValueChange.

onCheckedChange: (Boolean) -> Unit nghĩa là "một đoạn code nhận vào một giá trị true/false". So với onClick: () -> Unit của AppButton, chỉ khác là có thêm giá trị được đưa vào.

3. Bấm vào chữ cũng được → Modifier.toggleable

HTML 
<label>
  <input type="checkbox">
  Tôi đồng ý
</label>
Compose 
Row(
    modifier = Modifier.toggleable(
        value = checked,
        role = Role.Checkbox,
        onValueChange = onCheckedChange
    )
) {
    Checkbox(checked = checked,
        onCheckedChange = null)
    Text("Tôi đồng ý")
}

toggleable biến cả Row thành vùng bấm, giống <label> bao quanh <input>. Lúc này Checkbox nhận onCheckedChange = null ("không tự xử lý bấm") để không có hai chỗ cùng nhận cú bấm. role = Role.Checkbox báo cho trình đọc màn hình biết đây là checkbox, giống thuộc tính role trong HTML.

5. Nhiệm vụ

Bước 1: trang mới. Tạo SettingPage.kt, route "setting", và thêm link từ TemplatePage. Thử trước Checkbox và Switch thô như mục 1 để thấy chúng chạy.

Bước 2: tạo ui/components/form/AppSwitch.kt. Code mẫu (đã build thử, chạy được):

@Composable
fun AppSwitch(
    label: String,
    checked: Boolean,                    // trang đưa vào: đang bật hay tắt
    onCheckedChange: (Boolean) -> Unit,  // báo cho trang biết giá trị mới
    modifier: Modifier = Modifier,
) {
    Row(
        modifier = modifier
            .fillMaxWidth()
            .toggleable( // cả dòng bấm được, giống <label>
                value = checked,
                role = Role.Switch,
                onValueChange = onCheckedChange
            )
            .padding(vertical = 8.dp),
        verticalAlignment = Alignment.CenterVertically
    ) {
        Text(text = label, color = colors.text, modifier = Modifier.weight(1f)) // chữ bên trái, đẩy switch sang phải
        Switch(
            checked = checked,
            onCheckedChange = null, // Row đã lo việc bấm
            colors = SwitchDefaults.colors(
                checkedTrackColor = colors.primary,
                checkedThumbColor = colors.white,
                uncheckedTrackColor = colors.light,
                uncheckedThumbColor = colors.secondary,
                uncheckedBorderColor = colors.secondary,
            )
        )
    }
}

Bước 3: tự viết AppCheckbox trong cùng thư mục, theo mẫu AppSwitch. Khác biệt: Checkbox đứng trước chữ, cách nhau 8dp, role = Role.Checkbox, và dùng CheckboxDefaults.colors(...) như bảng ở mục 4.

Bước 4: dựng trang theo hình kết quả.

  • Nhóm "Chung" và "Sở thích" là 2 AppCard của bạn.
  • Mỗi switch/checkbox có một State riêng ở đầu SettingPage, ví dụ var notify by remember { mutableStateOf(true) }.
  • Riêng "Chế độ tối" thì không cần State mới. Dùng luôn ThemeManager có sẵn của app (cũng là một State, nhưng dùng chung cho cả app): 
    AppSwitch(
    label = "Chế độ tối",
    checked = ThemeManager.isDarkMode.value,
    onCheckedChange = { ThemeManager.setDarkMode(it) }
)
  • Nút "Lưu cài đặt": AppButton(..., enabled = agreed). AppButton của bạn đã có tham số enabled, giống thuộc tính disabled của <button>, chỉ là ngược nghĩa.

Bước 5: kiểm tra. Bấm vào chữ và vào công tắc đều phải bật/tắt được. Bật "Chế độ tối" thì cả app đổi theme. Sau đó vào lại LoginPage, ở đó theme cũng đã đổi, vì ThemeManager dùng chung.

Muốn có checkbox "Chọn tất cả" với trạng thái "chọn một phần" (dấu gạch ngang, giống indeterminate trong HTML)? Compose có TriStateCheckbox, hãy hỏi agent. Lưu ý: tắt app rồi mở lại thì các lựa chọn sẽ mất, vì lưu lâu dài cần kiến thức ngoài phạm vi UI. Báo "xong bài 12" khi xong.
